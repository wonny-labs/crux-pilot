1. The RT1060 manual copy is Rev. 3 (07/2021) from a third-party host. Compare against NXP's own download (account needed) and check later revisions and the errata sheet (`IMXRT1060CE` errata not fetched; the datasheet `IMXRT1060CEC.pdf` is reachable but was not read).
2. Not public or not found: RT1060 Security Reference Manual, AN12079, AN4581, CST user guide, AN12107. Open: SRK_REVOKE bit semantics on RT1060 (B-62), SEC_CONFIG[0] (B-23), HAB event contents in Open configuration with a blank SRK hash (#141 A13 rest).
3. Behaviours stated only as generic text and never tested: invalid FCB or IVT falls to the serial downloader (B-6), what happens with SDP disabled (B-21), calling `ROM_RunBootloader` from an application (B-33), ROM API from XIP code (B-35).
4. The NOR secondary-image algorithm (B-48) and its interaction with `runBootloader` image selection (B-32). The SDK-guide statement that redundant boot needs a plugin (B-50) conflicts with it.
5. The UART disable polarity (B-22).
6. SPSDK v3.13.0 `mimxrt1060` memory map disagrees with the RT1060 manual (B-16). Check that `nxpimage` output for RT1060 is not affected before using it for the bootloader.
7. Flashloader binaries and licences: the SDK guide shows `ivt_flashloader.bin` and `ivt_flashloader_signed.bin`, but where they come from and under what licence was not read (B-14, B-18).
8. NXP GUI-only items: MfgTool is a Windows tool. Whether a scripted `sdphost` plus `blhost` path is documented for RT1060 (not only a community post) was not found.
9. HAB second-stage authentication on RT1060 (B-65) needs the HAB API table layout from a public RT1060 source.
10. RT1176 manual, ROM redundancy, and "Wipe Invalid Image" (B-81, B-83).
