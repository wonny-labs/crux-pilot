## How to read this

**Evidence levels.** A cell names the highest level that the repository records for the component's current code, then the other levels that exist. A higher level is closer to a board. It does not include the lower ones: none implies another, as [README.md](../README.md#development-and-target-environments) and [AGENTS.md](../AGENTS.md#validation-and-evidence) state.

- **E1 Host test.** CTest, GoogleTest or Python tests on Linux Host, with fakes or a Host provider. It does not prove Zephyr behaviour, timing or any board.
- **E2 `native_sim`.** Ztest, Twister or an image on Zephyr `native_sim`, with the host TCP stack and test entropy. It does not prove target peripherals, timing or persistence.
- **E3 EVKB build.** The selection compiles and links for `mimxrt1060_evk@B//qspi` and nothing runs. It does not prove boot, peripheral behaviour or resource use.
- **E4 physical board.** A recorded run of identified firmware on an identified board, limited to its documented scenario. It does not prove other boards, cards, wiring or endurance, nor the current code if the run was of earlier code.

The validation limits are in the README ([Host tests, `native_sim` runs and target cross-builds do not prove physical operation](../README.md#development-and-target-environments)) and in [Engineering and validation boundaries](architecture.md#engineering-and-validation-boundaries). A board run that was `INCONCLUSIVE`, or that ran code since replaced by a redesign, is named in the cell and is not counted as E4. A completed run of an earlier revision counts only as its narrow slice, with the revision named. Where a result is a narrow slice, the cell says which slice ([status of a hypothesis or exit criterion](architecture.md#status-of-a-hypothesis-or-exit-criterion)).

**Zephyr composition** means what the repository builds, not what a product could build:

- `module` means the selection is in `zephyr/CMakeLists.txt` and `zephyr/Kconfig`, with the port under `components/<name>/ports/zephyr`.
- `tests/ only` means every composition that selects it sits under `tests/`.
- `samples/` or `templates/` is named where a composition outside `tests/` exists.
- `none` means no Zephyr selection or port exists for it.
- Compositions in other repositories, such as `crux-controller`, were not examined.

**Provisional tier.** The tier is [ADR-0001 Decision 4](decisions/0001-application-boundary-and-api-stability.md#decision-4-api-stability-and-change-policy) applied by the author to what this table records. It is provisional until a tier table and `Status:` lines exist in the public headers, which the ADR lists as follow-up changes. Nothing is Stable, because nothing is Stable before `v1.0`. Each row shows one of these outcomes:

- **Experimental** where the rule forces it: no Zephyr composition outside `tests/` in this repository.
- **Unstable** where the Zephyr composition outside `tests/` and the rest of the ADR's description ("an adopted contract with a consumer and tests") are all shown by the sources cited in the row.
- **Unassigned** or **Internal** otherwise, as stated in the cell.

ADR-0001 is Accepted (12 November 2026, with D10 limited to phase 1). Its follow-up change 5, which assigns a tier to each interface and puts `Status:` lines in the headers, is not done, so every tier here stays provisional.

## Notes

- **Board results are narrow slices at earlier revisions.** `file` on the microSD has one board and one card, at the source revisions named in its row, and is not a result for the code at the revision above. Netif and Sockets have one narrow E4, a reduced non-qualifying boot of the M5 image at `94a4a7da`. The Time and controller-sample runs are of code since replaced by a redesign and are not counted. GPIO item P1 is a plan with no result.
- **Management components.** Nothing ran on a board ([guide](management-in-a-product.md)). Every one is at most E3, and `reboot` is E1.
- **E3 is a build.** The bench image compiles and links and refuses to start. It does not show that a handshake, a login, entropy or timing work on the board.
- **Out-of-tree consumers.** `crux-controller` is a separate repository and was not examined. A composition there is not counted above. If one exists for a component marked Experimental, the label needs that record before it changes.
- **How the rows were made.** Each cell was read from `components/<name>/CMakeLists.txt`, the files under `ports/`, `zephyr/Kconfig`, `zephyr/CMakeLists.txt`, [tests/README.md](../tests/README.md), the cited contract or validation document and, for E4, the evidence directory itself. Where the sources conflict, the cell quotes the one that holds and names the other.
