# M6 SPI Interface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a small portable C17 synchronous SPI transceive contract with Host and Zephyr providers.

**Architecture:** One Zephyr-composed peripheral is selected through the `crux-spi0` alias. The portable operation exchanges equal-length byte buffers in one full-duplex transaction; frequency, mode, bit order, and chip select stay in Devicetree, and the provider fixes the word size at 8 bits. Native driver synchronization remains driver-specific; Crux adds no lock.

**Tech Stack:** C17, CMake/CTest, Zephyr SPI API and Devicetree, Zephyr SPI emulation controller on `native_sim`, Python build checks.

**Spec:** Issue #31's reviewed SPI/I2C scope and locking decision.

## Global Constraints

- No physical hardware use or qualification claims.
- Do not expose or modify QSPI/FlexSPI Flash paths or M4 resources.
- Keep the public header independent of Zephyr/NXP types.
- One call is synchronous and one driver transaction; driver controls CS timing.
- No Crux deadline or lock; document native-driver blocking/concurrency limits.
- Require distinct, non-overlapping TX and RX buffers, both non-null, and length greater than zero.
- Reject Devicetree `spi-hold-cs` (the contract has no explicit CS release operation), half-duplex and TI frame format.

## Review Focus

- Invalid pointers and zero length fail before native calls.
- Devicetree fixes frequency, mode, bit order, and CS for the selected peripheral; the word size is fixed by the provider.
- Host and native_sim tests cover loopback data and native error propagation.
- Public CMake target must not expose private Zephyr dependencies.
- No current Crux SPI consumer or physical peripheral route is evidenced; treat this as an enabling slice.
