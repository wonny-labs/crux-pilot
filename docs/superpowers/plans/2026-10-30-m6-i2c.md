# M6 I2C Interface Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a small synchronous C17 I2C transfer contract with Host and Zephyr providers, validated by deterministic software consumers.

**Architecture:** Expose one composed controller alias and a 7-bit target address per call. Preserve the caller's buffers for the duration of the synchronous call; let the Zephyr driver's transfer lock serialize each bus transaction. Provide a memory-backed Host fixture and a `native_sim` Zephyr emulation test, without selecting a physical board bus until a concrete Crux consumer requires one.

**Tech Stack:** C17, CMake/CTest, Zephyr I2C API, Zephyr `i2c_emul` on `native_sim`, Python build checks.

**Spec:** M6 Phase 4 in the supplied goal brief and Issue #31's reviewed SPI/I2C scope and locking decision.

## Global Constraints

- No hardware operation or physical qualification claim.
- No Crux-owned lock; use the native driver's per-controller synchronization.
- Do not bind the Crux alias to M4-owned FlexSPI/Flash resources.
- Keep the public header independent of Zephyr/NXP headers.
- Return after synchronous native transfer completion; provide no Crux deadline and document that a native driver may block according to its own timeout behavior.
- Accept only 7-bit addresses and individual message lengths representable by Zephyr's `uint32_t` I2C message length.

## Review Focus

- Invalid address, null buffers, empty request, and oversized messages are rejected before the provider call.
- Combined write/read is a single repeated-start transaction, preserving register-read semantics.
- A failed transfer returns an error without claiming that a read buffer is unchanged.
- Provider selection must fail at build time when the `crux-i2c0` alias is absent or disabled.
- The API must not add a second synchronization layer around native bus transactions.

**Interfaces:**
- Produce `crux_i2c_transfer(uint16_t address, const uint8_t *tx_data, size_t tx_length, uint8_t *rx_data, size_t rx_length)`.
- Zero TX or RX length omits that direction; both zero is invalid. Both nonzero means one combined transfer with repeated start.
- Buffers are borrowed until return and never retained. Public status uses existing `crux_status_t` values.
